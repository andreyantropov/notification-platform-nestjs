# Инфраструктура и окружение

Платформа разделяет инфраструктуру на два независимых контура: **локальное окружение разработки** (в этом репозитории) и **продуктовую инфраструктуру** (во внешнем репозитории). Это реализует принцип разделения ответственности: команда разработки владеет логическими контрактами системы, операционная команда — ресурсами её запуска.

## Границы ответственности

| Контур                         | Содержимое                                                                          | Репозиторий                        | Принцип изменения                                                                       |
| :----------------------------- | :---------------------------------------------------------------------------------- | :--------------------------------- | :-------------------------------------------------------------------------------------- |
| **Локальное окружение**        | Docker Compose, топология RabbitMQ (`definitions.json`), шаблоны `.env`             | Этот монорепозиторий               | Изменяется синхронно с кодом сервисов. Топология очередей — часть контракта приложения. |
| **Продуктовая инфраструктура** | Nginx, Keycloak, Grafana-дашборды, K8s-манифесты, OTel Collector pipelines, секреты | Внешний репозиторий инфраструктуры | Адаптирует логические контракты под конкретное окружение без изменения бизнес-логики.   |

## Инфраструктурные механизмы как часть архитектуры

Некоторые инфраструктурные механизмы являются неотъемлемой частью архитектурных контрактов платформы и реализуются в коде сервисов, а не в конфигурации окружения:

### Graceful Shutdown

Корректное завершение работы — обязательный контракт всех сервисов платформы. Он обеспечивает целостность данных при деплоях и перезапусках:

1.  HTTP-сервер прекращает принимать новые запросы, завершая текущие.
2.  AMQP Consumer останавливает потребление, завершает обработку текущего сообщения и отправляет ACK/NACK.
3.  OTel SDK выполняет flush незавершённых batch'ей телеметрии.
4.  Процесс завершается с кодом `0`.

Максимальное время graceful shutdown: **30 секунд**. Использование `process.exit()` в бизнес-коде запрещено, так как оно нарушает этот контракт.

### Топология очередей как код

Конфигурация RabbitMQ (exchange, очереди, binding, DLQ-стратегии) версионируется вместе с кодом приложения в `infra/rabbitmq/definitions.json`. Это гарантирует идентичность топологии во всех окружениях и делает изменения очередей явными и ревьюируемыми как часть кодовой базы.

## Наблюдаемость как архитектурный контракт

Стек наблюдаемости (OTel Collector → Prometheus / Tempo / Loki → Grafana) является обязательной частью платформы, а не опциональным дополнением. Сервисы экспортируют телеметрию по протоколу OTLP/HTTP, не зная о конечном бэкенде.

- **Локально:** Минимальный стек развёрнут через Docker Compose для отладки телеметрии.
- **Продуктивно:** Конфигурация дашбордов, алертов, sampling-стратегий и экспортёров находится во внешнем репозитории инфраструктуры.

Граница контракта: сервисы гарантируют формат и семантику экспортируемых данных; инфраструктура гарантирует их доставку, хранение и визуализацию.

## Продуктовая инфраструктура

Во внешнем репозитории инфраструктуры конфигурируются:

- **Nginx**: маршруты API, TLS-терминация, rate limiting.
- **Keycloak**: клиенты, роли, realm-конфигурация.
- **Grafana**: преднастроенные дашборды (Platform Overview, Delivery Pipeline, Channel Health, System Resources), алерты.
- **Оркестрация**: K8s/Docker Swarm манифесты, HPA, сетевые политики, секреты.
- **OTel Collector**: продуктовые pipelines, sampling, экспортёры.
