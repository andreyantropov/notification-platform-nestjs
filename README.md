# notification-platform

Событийно-ориентированная платформа уведомлений. Обеспечивает независимый прием, обогащение данных и стратегическую маршрутизацию по каналам доставки.

**Стек:** NestJS · Fastify · RabbitMQ · OpenTelemetry · TypeScript · pnpm

---

## Архитектура и документация

Подробное описание архитектуры, схемы взаимодействия сервисов и принятые технические решения (ADR) находятся в изолированной папке проекта.

**[Перейти к архитектурной документации](./docs/)**

Внутри документации вы найдете:

- Схемы топологии RabbitMQ (Exchanges, Queues, Routing Keys).
- Диаграммы последовательности обработки запроса.
- Контракты данных между микросервисами.

## Структура репозитория

```bash
├── apps/                 # Микросервисы платформы
│   ├── receive-service/  # Сервис приема, валидации и обогащения запросов
│   └── delivery-service/ # Сервис-воркер, отправляющий уведомления по стратегиям
├── docs/                 # Архитектурная документация и схемы
├── infra/                # Инфраструктура локальной разработки (RabbitMQ)
├── libs/                 # Переиспользуемые внутренние библиотеки
└── docker-compose.yml    # Локальные зависимости (брокер, observability)
```

> 💡 Это **монорепозиторий** на базе pnpm workspaces. Все команды запускаются из корня.

## Быстрый старт

### Требования

- **Node.js** ≥ 20.x
- **pnpm** ≥ 9.x
- **Docker** & **Docker Compose**

### 1. Запуск инфраструктуры

Поднимите локальный брокер RabbitMQ и стек наблюдаемости. Сами микросервисы запускаются отдельно для удобного дебага.

```bash
docker compose up -d
```

### 2. Настройка окружения

Скопируйте шаблоны переменных окружения для каждого сервиса:

```bash
cp apps/receive-service/.env.example apps/receive-service/.env
cp apps/delivery-service/.env.example apps/delivery-service/.env
```

> ⚠️ Отредактируйте `.env` файлы при необходимости. Значения по умолчанию подходят для локального запуска.

### 3. Установка и запуск

```bash
pnpm install
pnpm run start:dev:receive   # http://localhost:3000
pnpm run start:dev:delivery  # http://localhost:3001
```

Сервисы запустятся в режиме hot-reload. Swagger UI доступен по адресу `http://localhost:3000/docs` (receive-service).
